There are actually **two independent problems**: 1. `symInf` doesn't get `.inf-glow-small`, despite the CSS existing for it. 2. More importantly, if the SVG is being replaced during every recalculation while already infinite, **any CSS animation attached to that SVG gets restarted**. I particularly agree with Claude's observation about: > `dEl.innerHTML !== newDamageText` That's a bad way to determine whether an SVG needs replacing. You're comparing your source representation against the browser's parsed/serialized DOM representation. **DOM equality is not string equality.** The transition guard is much more robust: ```js if (isInfCurrent) { if (!prevIsInf) dEl.innerHTML = symInf; } ``` So the SVG gets created **once when entering infinity**, then remains alive while the user changes the numbers. I'd use Claude's fix here essentially as written. One additional thing I'd do: **don't animate the SVG's actual `stroke` or `filter`**.
